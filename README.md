# SONAE — 備蓄台帳 × 安否確認

防災備蓄品を「リース資産」と同じ粒度（ロット単位・満了日つき）で台帳管理し、
災害時の安否確認・災害対策本部運営までを一気通貫で支える BCP プラットフォームの**構想検証用モックアップ**です。

> 表示されているデータはすべて架空の企業「株式会社ミナトテック」の想定データです。

## 画面

| パス | 画面 | 内容 |
|---|---|---|
| `/` | ダッシュボード | 実効充足率・期限アラート・年間換算コスト・進行中インシデント |
| `/coverage` | 充足率・基準管理 | 基準セット（東京都条例／内閣府／自社）を切り替えて拠点×品目のヒートマップを再計算 |
| `/stock` | 備蓄ロット台帳 | ロット単位の在庫・期限・取得単価・発注番号。QR棚卸 |
| `/renewal` | 更新計画・コスト | 36ヶ月の満了スケジュール、年度別予算、平準化シミュレーション、防災原価の内訳 |
| `/command` | 災害対策本部 | 滞留人数 × 実効在庫 ＝ 残存日数。経過時間・受入れ人数のスライダーで再計算 |
| `/safety` | 安否確認 | 気象庁連動の自動発報ルール、通知チャネル、回答フォーム、発報履歴 |
| `/safety/D2026-014` | 回答集計 | 安否／出社可否／現在地の内訳、部署別回答率、個票、掲示板 |
| `/drills` | 訓練・監査記録 | 訓練実施記録、回答率の立ち上がり、BCP証跡サマリ |

### 事業者側コンソール（防災用品卸「みなと防災サプライ」の想定）

| パス | 画面 | 内容 |
|---|---|---|
| `/ops` | 需要パイプライン | 全顧客の満了予定を月別・品目別に集計。90日以内に満了する顧客リスト |
| `/ops/procurement` | 仕入計画・自社在庫 | 満了数量から発注必要数を算出。自社ロットの期限リスクとDC別配置 |
| `/ops/orders` | 更新受注・引取り | アラート→見積→承認→出荷のステージ管理、失注要因、逆物流 |
| `/ops/contracts` | 契約・預託資産 | 売切りと預託の比較、MRR、預託在庫の簿価、転換の余地と回収期間 |
| `/ops/economics` | 収支シミュレータ | 8つのスライダーで5年のP/LとキャッシュフローKPIを試算 |

## このモックで見せたい一点

安否確認と備蓄管理を**同じ人員マスタ**の上に載せると、対策本部で

> 「東京本社：滞留 148名、飲料水は 4.9日分、食料 4.3日分、簡易トイレ 4.1日分」

が発災直後に自動で出ます。ツールが分かれていると、この数字は人力の突き合わせでしか出せません。
`/command` のスライダー（経過時間・帰宅困難者の受入れ）を動かすと、枯渇する品目と時期が入れ替わります。

## 技術構成

- Next.js 16（App Router）／ React 19 / TypeScript
- Tailwind CSS v4
- 外部依存なし。全データは `lib/data.ts` で決定論的に生成（表示は毎回同じ）
- 算定ロジックは `lib/calc.ts` に集約（充足率・年間換算コスト・更新スケジュール・残存日数）

## 開発

```bash
npm install
npm run dev     # http://localhost:3000
npm run build
```

## Vercel へのデプロイ

このリポジトリを Vercel で Import するだけです（追加設定・環境変数は不要）。

## 参考にした基準・サービス

- 東京都帰宅困難者対策条例／同ハンドブック（飲料水 3L・食料 3食／人日 × 3日、毛布 1枚／人）
- トヨクモ 安否確認サービス2（気象庁連動の自動一斉送信、多チャネル通知、未回答者への自動再送、掲示板、訓練レポート）
